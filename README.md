# 就活ダッシュボード

就職活動の **進行状況・提出物・締切・重要事項** を1か所で管理できる Web アプリです。
スマホでもPCでも同じ画面から編集でき、内容はその場で保存されます。

インストール不要・サーバー不要で、HTML と JavaScript だけで動きます。

---

## できること

| 画面 | 内容 |
| --- | --- |
| **ホーム** | 応募社数・選考中・内定数の集計、期限切れ/直近の締切アラート、これからの予定、選考ステージの内訳、重要事項メモ |
| **企業** | 企業ごとの選考ステージ・志望度・業界・職種・マイページURL・メモ。説明会/面接/締切などの予定を企業に紐づけて管理 |
| **やること** | 提出物やタスクを期限つきで管理。「期限超過 / 今日 / 3日以内 / 1週間以内」に自動で仕分け |
| **カレンダー** | 面接・締切・やることを月表示でまとめて確認 |
| **ストック** | ガクチカ・自己PR・志望動機などの回答を保管。**文字数カウント付き**（ESの字数制限対策）。持ち物リストなどのメモも |
| **設定** | プロフィール、テーマ、バックアップの書き出し/読み込み、端末間の同期 |

その他:

- **スマホ対応** — 画面下のタブで操作。ホーム画面に追加すればアプリのように起動できます
- **オフライン対応** — 電波がなくても開けます（面接会場で確認できます）
- **ダークモード** — 端末の設定に自動で追従します
- **サンプルデータ** — 設定画面から入れて、使い方をすぐ試せます

## 公開する（GitHub Pages）

### かんたんな方法（Actions 不要）

1. このリポジトリを GitHub に push します
2. **Settings → Pages** を開きます
3. **Source** で `Deploy from a branch` を選び、ブランチと `/ (root)` を指定して **Save**
4. 数十秒後に `https://<ユーザー名>.github.io/Job-hunting-support/` で開けます

### Actions で自動デプロイする方法

`main` ブランチに push すると `.github/workflows/pages.yml` が自動で公開します。
**Settings → Pages → Source** で `GitHub Actions` を選んでおいてください。

### 手元で動かす

```sh
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

> ブラウザのセキュリティ制限（ES モジュール）のため、`index.html` をファイルとして
> 直接開くのではなく、上のように簡易サーバー経由で開いてください。

## データの保存場所と、スマホ⇔PCの同期

### 保存場所

データは **開いているブラウザの中（localStorage）** に保存されます。
サーバーには送信されません。そのため:

- ブラウザの履歴やサイトデータを削除すると **データも消えます**
- **別の端末とは自動では共有されません**

**設定 → データ → バックアップを書き出す** で、定期的に JSON を保存しておいてください。
書き出したファイルは「バックアップを読み込む」で元に戻せます。

### 端末間で同期する（任意）

スマホとPCで同じデータを見たい場合は、**GitHub Gist** を使った同期を設定できます。

1. <https://github.com/settings/tokens> を開く
   - 画面からたどる場合: 右上のアイコン → **Settings**（リポジトリの Settings ではなく
     アカウントの Settings）→ 左サイドバーを一番下までスクロールして
     **Developer settings** → **Personal access tokens** → **Tokens (classic)**
2. **Generate new token** → **Generate new token (classic)** を選ぶ
3. **Note** に分かりやすい名前、**Expiration** に有効期限を入れる
4. **Select scopes** で **`gist` だけ** にチェックして **Generate token**
   - 「Fine-grained tokens」は Gist に対応していないので、**classic** を使ってください
5. 表示されたトークンをコピー（1回しか表示されません）
6. アプリの **設定 → 端末間の同期** を開く

**1台目（いつも使う端末）**

| 入力欄 | 入れるもの |
| --- | --- |
| アクセストークン | 手順5でコピーした `ghp_…` |
| Gist ID | **空のまま** |

**「クラウドに保存する」** を押すと非公開の Gist が作られ、**Gist ID** が自動で入ります。
この ID を控えておいてください。

**2台目（もう一方の端末）**

| 入力欄 | 入れるもの |
| --- | --- |
| アクセストークン | 1台目と同じ `ghp_…` |
| Gist ID | 1台目に表示された ID |

**「クラウドから取り込む」** を押すと1台目のデータが入ります。
以降はどちらの端末でも、両方のボタンが使えます。

「自動で同期する」を ON にすると、起動時に取り込み、変更時に自動保存します。

> **トークンの扱いについて**
> トークンはその端末のブラウザ内にのみ保存されます。
> **Gist に書き込むデータにもバックアップファイルにもトークンは含まれません。**
> （Gist にトークンが入ると GitHub に漏洩と判定され、トークンが自動で無効化されます）
> 権限は `gist` のみに絞ってください。共用のPCでは同期を設定しないことをおすすめします。
> 作られる Gist は **secret（非公開）** ですが、URL を知っている人は閲覧できます。
> 実名や連絡先など、知られて困る情報は書かないようにしてください。

### うまくいかないとき

設定画面の **「接続をテスト」** を押すと、原因を切り分けて教えてくれます。

| 表示されるもの | 原因と対処 |
| --- | --- |
| トークンが GitHub に認識されませんでした | トークンの文字列が違います。`ghp_` から末尾まで全部コピーできているか、前後に空白が入っていないか、有効期限が切れていないか、Gist ID 欄と入れ違いになっていないかを確認してください |
| `gist` 権限がありません（Fine-grained） | **Tokens (classic)** ではなく Fine-grained token を作っています。classic で作り直してください |
| `gist` 権限がありません（現在の権限: …） | classic ですが `gist` にチェックが入っていません。GitHub のトークン設定画面でチェックを入れて更新してください |
| Gist が見つかりません | Gist ID が違うか、その Gist が削除されています。1台目で「クラウドに保存する」を押し直すと作り直せます |
| GitHub に接続できませんでした | 通信環境の問題です |

#### 1回目は成功するのに、2回目から「トークンが無効です」になる

初期のバージョンに、**同期データの中にアクセストークンを書き込んでしまう不具合**が
ありました。GitHub がそれを漏洩として検知し、トークンを自動的に無効化するため、
1回目は成功し、2回目や別の端末では必ず失敗する、という状態になります。

現在は修正済みですが、影響を受けた場合は次の手順で復旧してください。

1. 最新版に更新する（`git pull`、公開サイトなら再デプロイ）
2. <https://gist.github.com/> で、作られた Gist を **削除する**
   - Gist は過去の版も残るため、上書きではなく削除が必要です
3. <https://github.com/settings/tokens> で、古いトークンを **削除する**
4. トークンを**新しく作り直す**（classic / `gist` のみ）
5. 新しいトークンでもう一度設定する（1台目は Gist ID を空のまま）

修正前に「バックアップを書き出す」で保存した JSON にもトークンが含まれています。
そのファイルは破棄するか、テキストエディタで `"token"` の行を空にしてください。

トークンは一度しか表示されないので、分からなくなったら**作り直すのが早い**です。
古いトークンは GitHub の一覧から削除しておくと安全です。

### 同期がぶつかったとき

両方の端末で別々に編集すると、内容が食い違います。
アプリは自動で結合せず、**後から「クラウドに保存する」を押した側の内容が残ります**。
編集を始める前に「クラウドから取り込む」を押す習慣をつけると安全です。

## ファイル構成

```
index.html              画面の骨組みとアイコン
manifest.webmanifest    ホーム画面に追加するための設定
sw.js                   オフライン用の Service Worker
css/style.css           スタイル（ライト/ダーク、スマホ/PC）
js/
  app.js                起動・画面の切り替え・ナビゲーション
  store.js              データの保存と読み込み、選考ステージなどの定義
  utils.js              日付・文字列・DOM のヘルパー
  ui.js                 モーダルと入力フォームの組み立て
  sync.js               GitHub Gist との同期
  sample.js             サンプルデータ
  views/                各画面（dashboard / companies / tasks / calendar / stock / settings）
```

データを増やす・項目を足すときは `js/store.js` の定義（`STAGES`、`EVENT_TYPES`、
`TASK_CATEGORIES`）を編集すると、各画面に自動で反映されます。
